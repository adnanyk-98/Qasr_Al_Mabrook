# About Us locale metadata and content dependency

The production English and Arabic About Us routes currently render the safe fallback titles (“About” / “حول”) and localized unavailable-content messages. The repository has no authoritative About Us copy or seed fixture. The application reads `static_pages` and `static_page_translations`, selecting a `PUBLISHED` `about-us` page and its locale translation; it falls back to the English translation only when an English row exists. A fallback response on both routes shows that production is not returning published About Us content, but this repository task does not query or change the shared database.

Keep both routes `noindex, follow` while the requested exact-locale content is unavailable, and omit `hreflang` rather than treating fallback text as an equivalent translation. The site owner must provide approved English and Arabic page titles and body copy, plus any SEO titles and descriptions that should be used. Publish an exact translation for each locale through the normal content workflow; reciprocal production-canonical alternates will then be emitted automatically. Do not invent business claims or publish translations based only on the fallback.
